# 软件内更新

Roger 从 v0.4.0 起支持在软件内下载并安装更新。完整安装器和便携包都包含独立组件 `Roger.Updater.exe`，无需打开浏览器下载更新包。

公开的 v0.3.0 及更早版本没有独立更新组件，需要先下载安装 v0.4.0，或替换为完整的 v0.4.0 便携目录；之后才能通过软件内更新升级到更高版本。手动安装前请从托盘菜单退出旧版。升级保留本地配置和监控记录。

## 使用

在 Roger 的“版本与更新”页面点击“检查更新”。发现更高版本、所需附件和校验清单后，可点击“下载并更新”。页面显示下载字节数和进度，下载期间可取消；失败后可重试。

下载完成会核对 SHA-256，复制到管理员受保护缓存并再次校验。独立组件就绪后，Roger 保存历史、停止后台任务并正常退出。组件确认 Roger 已退出并收到本次安装确认后，才开始更新：

- 安装版使用 Release 内的安装器，沿用当前安装目录，显示安装进度，无须手动下载和解压。
- 便携版验证并解压 ZIP，备份被替换的程序文件；替换失败时尝试恢复原文件。

完成后核对程序的实际版本，再重新打开 Roger。失败也会尝试重新打开现有程序；便携恢复失败时，报告会指出备份位置。安装器自身的部分失败无法保证完整回滚，可用完整安装器重新安装。依赖需要重启 Windows 时会提示用户手动重启，不会自动重启电脑。

重新进入版本页可查看上次结果并打开日志。配置、提醒、历史和优化记录不会作为更新载荷替换。启动时检查选项只查询版本，不自动下载或安装。当前已经是最新版本时，更新按钮保持禁用。

## 发布与开发

仅支持 Windows x64 正式版本，标签使用 `v主版本.次版本.修订号`。所配置的 GitHub 仓库需要提供：

- 安装版：`Roger-Setup-版本号-x64.exe`。
- 便携版：`Roger-win-x64.zip`，直接包含 `Roger.exe` 和依赖，不额外套文件夹。
- `SHA256SUMS.txt`：每行采用 `64位SHA256  文件名`，必须含对应更新包条目。

现有 `scripts/package.ps1` 会生成这组附件。`scripts/publish.ps1` 会把自包含、单文件的更新组件放入便携输出目录，再由安装器一同包含。普通 `dotnet build` 产生的很小的 apphost 依赖旁边的运行时文件，不能单独充当更新组件；缺少完整组件时更新按钮保持禁用并显示原因。应用与组件使用同一版本参数构建。

只接受比当前程序集更新的正式版本，不降级或重复覆盖相同版本。GitHub 请求与重定向限定 HTTPS 官方域名；元数据、校验清单、下载和解压均有大小限制。下载包必须与发布清单及 GitHub 提供的摘要（如有）一致。SHA-256 校验用于验证下载完整性，不代替发行者的代码签名或消除 Windows SmartScreen 提示。

Roger 默认以管理员权限运行，更新组件继承该权限。程序不得关闭 Windows 安全防护来完成更新。安装器固定使用禁止自动重启、禁止强制关闭应用的参数；助手最长等候 Roger 退出两分钟，超时不修改程序文件。

## 缓存与日志

下载及最后结果在 `%LOCALAPPDATA%\Roger\updates`；受保护的安装载荷、日志及便携备份在 `%PROGRAMDATA%\Roger\updates\本次标识`。安装助手的运行时也在受保护缓存内解包。

安装缓存保留最近两次，其余超过七天、未被活动助手占用且没有目录联接的旧目录，在下次准备更新时回收。成功下载的原始文件当前保留用于诊断，不承诺磁盘占用硬上限；失败或取消的下载会清理本次不完整文件。日志和便携备份可能包含本机程序路径，提交问题时按需分享。
