# 提醒、进程排行和监控历史

这些功能只读取资源与硬件状态，不自动结束进程、修改优化选项或进行清理。数据保存在当前用户的 `%LOCALAPPDATA%\Roger` 目录，不上传到服务端。

## 异常提醒

异常页分别配置 CPU / GPU 温度上限、物理内存占用上限和各卷可用空间下限。默认 CPU 90°C、GPU 85°C、内存 90%、卷剩余空间低于 10%，持续 15 秒后提醒，同一项目冷却 300 秒。这些是可调整的提醒条件，不能替代设备厂商的温度或故障判定。

每个可读取温度的 CPU / GPU 分别判断，以稳定设备标识独立计算持续时间与冷却，不受概览显卡选择影响。只有连续有效采样才累计持续时间。设备读数缺失、长时间没有新采样或时钟回拨时，重新建立持续区间；不会把没有温度当成 0°C。静音模式照常记入事件，仅抑制托盘通知。Windows 是否实际显示通知取决于系统通知及免打扰设置。

配置写入 `alerts-options.json`，最近 500 条事件写入 `alerts-records.json`，采用临时文件与原子替换。重启后保留记录与事件冷却依据。损坏文件会保留，写入新记录前保存原始副本。清空事件记录不会重置当前运行中的冷却。

## 进程资源排行

每两秒枚举一次进程。CPU 使用率根据相邻两次内核与用户 CPU 时间差除以实际间隔，再按全机活动逻辑处理器数量归一。PID 与创建时间共同确定进程身份，避免 PID 重用造成错误速率。首笔数据需要建立基线。

内存显示工作集，其中可能包含共享物理页，不能把所有工作集相加当作整机内存占用。I/O 通过 Windows 进程计数器读取，包含文件、网络和设备操作，不等同于物理硬盘吞吐。权限受限、进程退出或计数器缺失的字段显示“不可用”。

只申请查询权限，不调整进程优先级、不终止进程、不启用调试特权。界面提供 CPU、工作集、I/O 读取、I/O 写入排序及名称 / PID 筛选，显示前 100 项。行悬停展示可读的程序路径和不可用原因。进程列表与路径不写入监控历史。

参考：[GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)、[GetProcessMemoryInfo](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getprocessmemoryinfo)、[GetProcessIoCounters](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getprocessiocounters)。

## 本地历史

监控期间按 UTC 分钟汇总，保存有效读数数量、和、最小值与最大值。界面使用当地时间显示。全区间平均值按有效读数数量加权，峰值来自原始采样；缺失值不加入分母，也不替换成零。

保存 CPU / GPU 使用率与温度、内存占用、网络收发及全部可见物理盘的读写合计。磁盘合计要求该方向的所有物理盘均提供有效数据；网络尚未建立基线或没有活动接口时保留缺失。GPU 标识随桶保存，切换设备时分开汇总，图表只显示所选显卡的数据。每次运行具有独立会话标识，重启之间的趋势不直接连线，超过三分钟的采样间隔也会断开。

历史位于 `history/history-yyyyMMdd.jsonl`，每个已完成的分钟区间追加一次，正常退出时写入最后的部分分钟。当前分钟可以在界面即时查看。强制结束进程时，尚未完成的当前分钟可能丢失。仅保留最近七天的查询数据；文件按天淘汰，因此边界日文件可能额外留存不足一天。内存最多保留 24,000 个区间。未运行的时间不补采样。

文件损坏行被跳过并给出提示，原始内容保留；后续追加不会吞掉前面的完整记录。导出为带 UTF-8 BOM 的 CSV，缺失字段为空，硬件名称按 CSV 规则转义并防止被表格软件当成公式。导出包含七天内全部设备，以标识区分；退出时等待正在进行的导出完成。

自动化检查使用专用临时目录和模拟快照，覆盖持续阈值、冷却、缺失、PID 重用、分钟聚合、显卡隔离、保存重载、损坏保留、过期与导出；优化更改通过模拟系统接口验证，不改动测试机器的设置。
